# FocusAnchor UX V2

多端交互设计表与 Codex 工程审查规范  |  2026-10-14  |  冻结草案 v1.0

用途：为主体 App、Form Kit 服务卡片和手表模块提供一致的页面分工、状态映射、数据事件与验收标准。本文件是目标设计，不是已实现证明。

## 0. 决策与证据边界

| 类别 | 内容 |
| --- | --- |
| 已确认产品决策 | 主体已签名 App 为唯一任务状态源；先在主体内接服务卡片；手表核心为一键闪念和当前第一步反馈；Focus=专注工作台+闪念收件箱；采用六张监测状态图与三张陪伴状态图。 |
| 来自现有源码静态审查 | 独立元服务与主体工程身份、API 版本不同；卡片 Preferences 未写回主体；Agent 输出缺持久化步骤契约；元服务工程 AppStorage 不是实际跨设备通道；既有主体有 KV 链路。 |
| 未验证/须 Codex 核实 | 卡片合并后的实时代码状态；Agent 能否生成有效步骤；真实手表一键 ASR；双端物理设备；图片是否已分割成九份；具体 ArkTS 类型和字段。 |
| 不可越界 | 不得将静态素材切换等同健康监测；单独 bpm 不能判定心理状态；不得把页面互相拉起等同数据同步。 |

## A. 页面功能、入口与导航

| 界面 | 关键呈现 | 主操作 | 明确禁止/改造 |
| --- | --- | --- | --- |
| Home | 小步伙伴主视觉、连接/心率摘要、当前任务与第一小步 | 开始/继续步骤；查看 Task | 去除独立 Guide Step 和 Use next task；不重复创建任务入口 |
| Task | 任务列表、录入、Agent 第一步、Deadline/优先级 | 文字/语音创建；帮我拆成第一步 | Speak task 只是录入方式；不复制任务业务状态 |
| Focus | 专注工作台 + 手表闪念收件箱 | 开始/暂停/继续；闪念查看/转任务 | 闪念不自动变 Task，不自动改变当前专注 |
| 主体服务卡片 | 当前任务、第一小步、精简状态 | 打开主体；合法时开始/完成 | 不可只改卡片本地 Preferences 即声称任务完成 |
| 手表任务 | 第一小步、状态图、反馈 | 完成/换一步/暂停 | 换一步 ≠ 完成；暂停 ≠ 步骤 DONE |
| 手表闪念 | 快速录音或现有快捷方式、保存提示 | 记录闪念/明确保存 | 未验证物理键能力不可作为唯一入口 |
| 手表监测 | 六种连接/数据状态、有效心率、陪伴视觉 | 查看与必要监测控制 | 不能仅凭 bpm 判断专注 |
| 设置/原账户 | 权限、设备管理、隐私及历史有效功能 | 沿用既有入口 | 导航变动不得删除已有 User/Cloud 功能 |

### A1. 空状态与用户操作结果

| 条件 | 用户看到 | 行为 |
| --- | --- | --- |
| 没有任何 Task | 温和空状态：从一件小事开始 | 跳 Task 创建，不产生虚构步骤 |
| 有 Task、无 Action | 已选任务 + “帮我拆成第一步”引导 | 到 Task 显式调用 Agent |
| 有 READY Action | 具体的第一小步 + 开始按钮 | 进入 Focus，标记 ACTIVE |
| 已有 ACTIVE Action | 同一小步 + 继续按钮 | 恢复现有专注，不重新生成 |
| Agent 不可用 | 明确失败/降级提示 | 只可使用有标记的真实规则降级，不冒充 AI |
| 新闪念同步到达 | Focus 收件箱新增条目 | 不切页面，不抢焦点，不修改当前 Task |

## B. 小步伙伴状态映射

### B1. 监测状态（MonitoringState）

| 状态 ID | 正式素材文字 | 必要条件 | 主展示 |
| --- | --- | --- | --- |
| CONNECTING | 连接中 | 连接请求中，尚未成功 | 手表监测、手机状态详情 |
| READING | 读取中 | 连接成功，等待有效新样本 | 手表监测、手机状态详情 |
| MONITORING | 持续监测 | 持续获得时效内有效样本 | 手表监测、Home 摘要 |
| SIGNAL_UNSTABLE | 信号不稳 | 信号/质量异常，读数不可靠 | 手表及 Home 摘要 |
| RECONNECTING | 等待重连 | 连接已断开，重试/等待中 | 手表及 Home 摘要 |
| STOPPED | 已停止 | 用户主动停用或监测关闭 | 手表及 Home 摘要 |

### B2. 陪伴状态（CompanionState）

| 状态 ID | 正式素材文字 | 安全触发规则 | 反馈性质 |
| --- | --- | --- | --- |
| STABLE | 专注稳定 | 经有效授权与可信上下文支持的稳定状态 | 非医学判断；不要求立即行动 |
| FLUCTUATING | 状态波动 | 充分依据或用户明确自述有波动 | 轻量询问，不诊断、不自动强干预 |
| SUPPORT_REQUESTED | 需要 FocusAnchor | 用户主动请求或同意接受支持 | 显示帮助入口与微步卡 |
| null/UNKNOWN | 无可信陪伴推断 | 未监测或证据不足 | 主视觉使用中性监测图，不编造状态 |

渲染优先级：无有效数据/异常时先显示 MonitoringState；数据正常且 CompanionState 可信时可显示陪伴图；陪伴未知时显示“持续监测”中性图。技术状态与陪伴状态分开存储。模拟数据必须标识 isSimulated，旧数据不得作为实时结论。

### B3. 素材清点与工程约束

Codex 必须核实每张图片是否为独立可加载资源、真实文件路径、资源 ID、显示端、缩放/安全区；若只有合成九宫格，不可当单状态资源直接加载。静态切换优先；本轮不新增动效框架。

## C. 跨端事件、统一状态与回写

| 事件 | 来源 | 唯一状态源的处理 | 更新/保障 |
| --- | --- | --- | --- |
| TASK_CREATED | 手机 Task | 持久化 Task | Home、Task |
| FIRST_STEP_REQUESTED | 手机 Task | Agent/已标明降级 → Action 持久化 | Home、Focus、卡片、手表 |
| STEP_STARTED | 手机/卡片/手表 | Action READY→ACTIVE、绑定 Focus 会话 | 全端刷新；幂等 |
| STEP_COMPLETED | 手机/卡片/手表 | 验证 actionId、revision，落库 DONE | 全端刷新；重复反馈去重 |
| STEP_CHANGE_REQUESTED | 手机/手表 | 选择/请求替代步骤，不冒充完成 | 全端一致 |
| FOCUS_PAUSED | 手机/手表 | 暂停会话及提醒，不标记 Action DONE | Focus、手表、卡片 |
| FLASH_CAPTURED | 手表 | 生成 flashId，先本地保存后可靠同步 | Focus 收件箱；当前 Task 不变 |
| FLASH_TO_TASK | Focus | 明确确认后生成 Task，保存关联 ID | Task、Focus；防重复 |
| MONITORING_CHANGED | 设备监测层 | 连接、数据质量、时间戳更新 | Home、手表；过期提示 |
| COMPANION_CHANGED | 授权状态/Agent | 更新可信支持状态 | Home、Focus、手表 |

### C1. 最小逻辑模型与字段语义

| 对象 | 必备语义 | 验证点 |
| --- | --- | --- |
| FocusAction | taskId, actionId, content, status, order, updatedAt, revision, source | 当前步骤持久化；可追溯代理/规则/手工来源 |
| FlashNote | flashId, content, sourceDevice, createdAt, syncStatus, convertedTaskId? | 离线保存、重试去重、转 Task 不丢原条目 |
| FocusSession | sessionId, taskId/actionId, IDLE/RUNNING/PAUSED | 暂停与步骤完成严格分离 |
| StateSnapshot | monitoringState, companionState?, bpm?, measuredAt?, isSimulated | 真实/模拟/过期区分，未知可表达 |
| SyncEvent | eventId, entityId, revision/baseVersion, origin, createdAt | 幂等、冲突、离线重发 |

字段是语义契约，不要求按同名新建重复接口；实际应优先复用 AppState、TaskFileService、WatchSyncService、当前卡片 API。现有按 updatedAt 合并策略需核对并发写入风险。

## D. Codex 只读审查与实施门禁

• G0：先检查 Git status/diff 与卡片接入工作是否仍在同工作区进行；不得覆盖未完成的并行修改。

• G1：输出“需求—现有文件/符号—证据—差距—拟修改文件—风险”矩阵；不存在的能力明确标记未实现。

• G2：先统一 Action 业务契约与主体持久化，再接卡片刷新与手表 KV；避免只改 UI。

• G3：优先局部改造 Home/Task/Focus，不删除原设置、提醒、语音、悬浮球、账户功能。

• G4：将九种素材绑定有来源的状态信号；禁止仅基于 UI 定时器轮播来暗示传感器实时状态。

• G5：不修改签名、bundle、SDK 或提交审核中的独立元服务；若必须修改，先列阻塞和影响。

• G6：区别静态检查、构建、模拟器、真机四类证据；不把编译成功描述为跨端验证。

## F. 交付格式与执行步骤

建议阶段：P0 页面与 Action/FlashNote 数据闭环；P1 角色九状态接入；P2 回归与真机/模拟器验证。先完成当前服务卡片集成并保留可回退基线，再启动本规范的代码变更。

Codex 交付必须包含：变更文件清单、入口迁移对照表、素材路径与状态映射、最终数据模型、接口复用清单、T01–T12 结果、独立服务卡片集成冲突、剩余阻塞。每项使用“已实现且验证 / 已实现未验证 / 接口存在但未接通 / 未实现”之一。
